# Skill评分反馈设计

日期：2026-04-15

## 1. 背景

当前系统已经完成：

- Skill 提交、审核、发布
- Skill 版本管理
- Skill 检索中心
- 真实 Zip 上传与下载
- 下载记录与历史版本下载

根据需求文档，下一步需要补齐员工在下载使用 Skill 后的评分反馈能力，并在 Skill 详情中展示评分概览与反馈内容，帮助员工判断 Skill 质量，也为后续统计管理提供基础数据。

本设计只覆盖 `评分反馈` 子项目，不包含 `站内通知联动`。通知将在下一轮以独立 spec 推进。

## 2. 目标

本轮交付目标：

- 员工下载 Skill 后可对该 Skill 提交评分和反馈
- 同一员工对同一 Skill 仅保留一条评分反馈记录
- 员工可修改自己的评分反馈
- Skill 详情页展示平均分、评分人数、评分分布、反馈列表
- 反馈实名展示
- 评分反馈进入操作日志

## 3. 关键规则

### 3.1 评分对象

- 评分反馈挂在 `Skill 系列（seriesId）` 上，而不是单个版本
- 评分记录中保留最近一次评分时对应的 `skillId`，用于记录评分时所针对的版本上下文

### 3.2 唯一性与修改规则

- 每个用户对每个 `seriesId` 只保留 1 条评分反馈
- 当用户再次提交评分反馈时，系统执行更新，不新增新记录
- 统计口径始终基于当前最新记录计算

### 3.3 评分前置条件

- 用户必须具备 `skill.rate` 权限
- 用户必须至少下载过该 Skill 系列一次
- Skill 必须对当前用户可见
- Skill 必须处于 `已发布` 且未下架状态
- 评分值只能是 `1-5`

### 3.4 展示规则

- 评分反馈实名展示
- 展示字段包括：评分人姓名、所属部门、评分时间、分值、反馈内容
- 反馈内容对所有具备 `skill.rating.view` 权限的用户可见

## 4. 范围

### 4.1 本轮包含

- 评分数据模型
- 提交/修改评分反馈接口
- 当前用户评分读取接口
- 评分概览接口
- 反馈列表接口
- Skill 详情页中的评分概览、我的评分、反馈列表
- 下载后评分校验
- 操作日志接入

### 4.2 本轮不包含

- 版本更新通知
- 审核任务通知
- 通知中心增强
- 反馈删除/屏蔽/无效标记
- 评分统计后台页面

## 5. 数据模型

新增表：`skill_ratings`

建议字段：

- `id`
- `series_id`
- `skill_id`
- `rater_id`
- `department_id`
- `department_name`
- `rating`
- `feedback`
- `created_at`
- `updated_at`

约束：

- `(series_id, rater_id)` 唯一

说明：

- `series_id` 用于唯一约束与统计汇总
- `skill_id` 记录该用户最近一次评分时针对的版本
- `department_id` / `department_name` 便于实名展示和后续统计

## 6. 权限设计

新增权限点：

- `skill.rate`
- `skill.rating.view`
- `skill.rating.manage`

本轮实际启用：

- 普通员工：`skill.rate`、`skill.rating.view`
- 审核员：同员工
- 管理员：全部可用

其中：

- `skill.rate` 控制提交/修改自己的评分反馈
- `skill.rating.view` 控制查看评分概览与反馈列表
- `skill.rating.manage` 本轮只预留，不强行落页面

## 7. 接口设计

### 7.1 提交或修改评分反馈

`POST /skills/:id/rating`

用途：

- 对指定 Skill 系列提交或修改当前用户评分

请求字段：

- `rating`
- `feedback`

处理逻辑：

- 先根据 `:id` 归一到 `seriesId`
- 校验当前用户是否下载过该 Skill 系列
- 若无记录则创建
- 若已有记录则更新

返回：

- 当前用户最新评分反馈详情

### 7.2 获取当前用户评分反馈

`GET /skills/:id/rating/me`

返回：

- 当前用户对该 Skill 系列的评分反馈
- 若不存在则返回 `null`

### 7.3 获取评分概览

`GET /skills/:id/rating-summary`

返回：

- 平均分
- 评分人数
- `1-5` 分值分布

### 7.4 获取反馈列表

`GET /skills/:id/ratings`

返回：

- 评分人
- 部门
- 评分值
- 反馈内容
- 更新时间

排序建议：

- 按 `updated_at desc`

## 8. 前端交互设计

在现有 `Skill 详情` 区域中新增三个板块：

### 8.1 评分概览

展示：

- 平均分
- 评分人数
- 1-5 分分布

### 8.2 我的评分反馈

规则：

- 已下载：展示评分表单
- 未下载：展示“下载后可评分”
- 已有评分：表单自动回填
- 再次提交：更新原记录

字段：

- 评分：`1-5`
- 反馈内容：文本输入

### 8.3 员工反馈列表

展示：

- 姓名
- 部门
- 评分
- 时间
- 反馈内容

## 9. 日志设计

评分反馈纳入操作日志，记录两类操作：

- `rate-create`
- `rate-update`

日志详情建议包含：

- `seriesId`
- `skillId`
- `skillName`
- `rating`
- `feedbackLength`
- `mode`：`create` / `update`

说明：

- 不在日志中存完整反馈正文，避免日志体积过大

## 10. 错误处理

建议统一错误文案：

- 未下载前评分：`下载后才可评分`
- Skill 不可见：`无权对该 Skill 评分`
- Skill 已下架：`该 Skill 已下架，无法评分`
- 非法分值：`评分必须在 1 到 5 分之间`
- 反馈为空但系统要求最小内容时：按前端表单规则给出明确提示

## 11. 测试策略

### 11.1 后端

- 已下载用户可首次评分
- 已有评分再次提交会更新，不新增
- 未下载用户评分失败
- 不可见或下架 Skill 评分失败
- 评分汇总统计正确
- 反馈列表实名返回正确

### 11.2 前端

- 未下载时不显示评分表单提交能力
- 已下载时可提交评分
- 已有评分时回填
- 修改评分后概览刷新
- 反馈列表展示实名信息

### 11.3 联调验收

- 员工下载 Skill 后可评分
- 同一员工重复提交时为更新
- 详情页显示平均分、人数、反馈列表
- 其他员工可查看实名反馈

## 12. 实施顺序

1. Prisma 模型与唯一约束
2. 后端评分接口与 e2e
3. 前端 Skill 详情评分区与反馈列表
4. 操作日志接入
5. 全量测试与构建验证
