# 云贝Skill管理系统真实Zip上传下载设计

## 1. 文档目标

本文档定义云贝Skill管理系统中 Skill Zip 包的真实上传、存储、下载能力设计，作为后续实现和测试的唯一设计基线。

本文档建立在以下既有事实之上：

- 基础平台、Skill 提交审核发布、版本管理、检索中心、下载记录基础能力已完成
- 当前系统仅保存 `packageName` 与 `packageSizeBytes`，尚未接入真实文件
- 需求文档已明确要求 Skill 通过 Zip 包上传与下载，大小上限 50MB，历史版本文件保留，员工可下载历史版本

本设计严格遵循以下约束：

- 仅参考需求文档 `D:\Project\yunbeiskill\docs\云贝Skill管理系统-需求文档.md`
- 系统为全新构建
- 新系统代码与配套文档均落在 `D:\Project\yunbeiskill\pcodex-openai`
- 不复用、不修改旧版本代码

## 2. 目标与范围

### 2.1 本次目标

- Skill 首次提交时支持上传真实 Zip 包
- Skill 新版本提交时支持上传真实 Zip 包
- Zip 文件存放在项目本地受控目录
- 员工可下载最新已发布版本，也可下载历史已发布版本
- 下载时自动记录下载人、时间、部门、Skill 名称、版本号
- 历史版本 Zip 文件长期保留，不覆盖旧文件

### 2.2 本次纳入范围

- 后端本地文件存储能力
- `skills` 表文件元数据扩展
- Skill 提交接口改造为支持 `multipart/form-data`
- Skill 版本提交接口改造为支持 `multipart/form-data`
- 真实下载接口
- 前端提交页、新版本页、下载按钮改造
- 上传与下载相关测试

### 2.3 本次明确不做

- 对象存储接入（MinIO / OSS / S3）
- 文件病毒扫描
- 文件断点续传
- 文件在线预览
- 安装器或自动安装能力
- 下载加速、临时签名 URL
- 下载统计导出

## 3. 设计结论

### 3.1 选型结论

本次采用“受控本地文件存储”方案：

- 文件物理存储在项目目录下
- 文件访问只能通过后端接口完成
- 不通过静态资源目录直接暴露文件
- 业务层只依赖文件元数据与文件服务，不直接操作磁盘路径

### 3.2 存储目录

默认存储目录：

```text
pcodex-openai/storage/skills
```

部署时通过环境变量覆盖：

- `SKILL_STORAGE_DIR`

目录规则：

- 由后端启动时确保目录存在
- 只允许 Skill 模块写入该目录
- 目录内不按用户可读 URL 暴露

### 3.3 文件命名策略

上传后不直接使用原文件名落盘，而是生成安全文件名：

```text
{skill-or-version-id}_{timestamp}_{random}.zip
```

设计原因：

- 避免重名覆盖
- 避免用户输入文件名引入路径风险
- 保证历史版本文件独立存在

用户原始文件名单独存库，用于前端展示和下载响应头。

## 4. 数据模型设计

### 4.1 现有字段保留

`skills` 表已存在：

- `packageName`
- `packageSizeBytes`

这两个字段继续保留，但语义调整为：

- `packageName`：前端展示使用的包名称，默认取原始文件名
- `packageSizeBytes`：真实上传文件大小

### 4.2 新增字段

建议在 `skills` 表新增以下字段：

- `packageOriginalName`
  - 原始上传文件名
- `packageStoredName`
  - 实际落盘文件名
- `packageRelativePath`
  - 相对存储路径，例如 `skills/xxx.zip`
- `packageMimeType`
  - 文件 MIME 类型，默认 `application/zip`
- `packageChecksum`
  - 文件校验值，建议 `sha256`
- `packageUploadedAt`
  - 文件上传时间

### 4.3 字段约束

- 新创建 Skill 必须有完整文件元数据
- 新版本 Skill 必须有完整文件元数据
- 历史已存在但无文件元数据的老数据允许继续展示
- 老数据点击下载时返回“文件不存在，请联系管理员重新上传”

## 5. 后端模块设计

### 5.1 新增文件存储服务

在 `apps/api` 中新增轻量文件存储服务，职责如下：

- 校验上传文件是否为 Zip
- 校验文件大小是否不超过 50MB
- 生成安全文件名
- 将文件写入本地目录
- 计算并返回文件元数据
- 提供文件读取流
- 在数据库事务失败或写盘失败时执行补偿清理

该服务只负责文件本身，不负责 Skill 业务权限。

### 5.2 Skill 提交接口改造

当前：

- `POST /skills`
- 使用 JSON 提交

调整后：

- `POST /skills`
- 使用 `multipart/form-data`

请求内容包括：

- 文本字段：名称、简介、说明、分类、来源、可见范围、项目、可见账号、版本说明等
- 文件字段：`packageFile`

规则：

- 无文件不允许提交
- 非 Zip 不允许提交
- 超过 50MB 不允许提交
- 文件写入成功后再创建 Skill 数据

### 5.3 Skill 新版本提交接口改造

当前：

- `POST /skills/:id/versions`
- 使用 JSON 提交

调整后：

- `POST /skills/:id/versions`
- 使用 `multipart/form-data`

请求内容包括：

- 文本字段：版本号、更新说明
- 文件字段：`packageFile`

规则：

- 新版本必须上传新 Zip
- 不允许复用旧文件路径覆盖历史文件
- 新版本创建成功后保留旧版本文件

### 5.4 真实下载接口

新增接口：

- `GET /skills/:id/download`

用途：

- 默认下载当前系列的最新已发布版本
- 当携带 `versionId` 查询参数时下载指定已发布历史版本

下载前校验：

- 用户已登录
- 具备 `skill.download`
- 用户对目标 Skill 可见
- 目标版本状态为 `PUBLISHED`
- Skill 未下架
- 文件元数据完整
- 磁盘文件真实存在

下载成功后：

- 返回文件流
- 设置正确的下载文件名
- 自动写入下载记录
- 记录版本号、Skill 名称、下载部门、时间

### 5.5 下载记录规则

下载记录不再由前端单独调用“登记下载”接口完成，而是并入真实下载流程。

结论：

- 保留当前下载记录模型
- 真实下载接口内部自动写入下载记录
- 前端不再把“记录下载”与“下载文件”拆成两个动作

### 5.6 权限规则

本次延续既有权限点：

- `skill.submit`
- `skill.download`
- `skill.download-history.view`

权限执行规则：

- 具备 `skill.submit` 才能上传新 Skill 或新版本
- 具备 `skill.download` 才能下载 Zip
- 具备 `skill.download-history.view` 才能查看历史下载与下载详情

Skill 可见范围仍按业务规则判断：

- `ALL_USERS`
- `PROJECT_MEMBERS`
- `SPECIFIED_USERS`

管理员按既有逻辑可查看全部已发布 Skill。

## 6. 前端设计

### 6.1 提交 Skill 页面

现有页面新增文件选择控件：

- 仅允许选择 `.zip`
- 展示文件名
- 展示文件大小
- 未选择文件时不允许提交

前端提交方式：

- 由 JSON 请求改为 `FormData`

### 6.2 新版本提交区域

现有“提交新版本”区域新增文件选择控件：

- 必须选择 Zip
- 必须填写版本号
- 必须填写更新说明
- 提交时使用 `FormData`

### 6.3 下载交互

现有“登记下载”按钮改为真实下载按钮：

- 在 Skill 详情页支持下载当前版本
- 在版本列表支持下载指定历史版本

用户点击后：

- 直接调用下载接口
- 由浏览器接收文件流并保存
- 下载成功后刷新历史下载列表和下载详情列表

### 6.4 老数据表现

对于已存在但没有真实文件的 Skill：

- 仍可展示在列表与详情页
- 下载按钮仍可显示
- 点击后给出明确提示：
  - “文件不存在，请联系管理员重新上传”

## 7. 错误处理

### 7.1 上传错误

明确提示以下场景：

- 未上传文件：`请上传 Zip 包`
- 扩展名不正确：`仅支持上传 Zip 包`
- 文件大小超限：`Zip 包大小不能超过 50MB`
- 表单字段缺失：沿用既有表单校验提示
- 文件写入失败：`文件保存失败，请稍后重试`
- 数据库存储失败：`Skill 保存失败，请稍后重试`

### 7.2 下载错误

明确提示以下场景：

- 无权限：`无权下载该 Skill`
- 不在可见范围：`无权下载该 Skill`
- 版本未发布：`仅可下载已发布版本`
- Skill 已下架：`该 Skill 已下架，无法下载`
- 文件不存在：`文件不存在，请联系管理员重新上传`
- 记录写入失败：`下载记录失败，请稍后重试`

### 7.3 一致性原则

上传成功定义：

- 文件已写入磁盘
- 数据库记录已成功写入

下载成功定义：

- 权限校验通过
- 文件可读取
- 下载记录成功写入
- 文件流成功开始响应

不允许出现“数据库成功但文件不存在”的持久化结果。

## 8. 兼容与迁移策略

### 8.1 兼容现有 Skill 数据

当前数据库中已存在测试数据，它们没有真实文件元数据。

兼容策略：

- 老数据不强制删除
- 老数据不强制回填伪文件
- 老数据继续可被检索与展示
- 老数据下载时明确提示缺文件

### 8.2 历史版本策略

- 新版本发布时，旧版本文件保留
- 历史已发布版本可继续下载
- 下架 Skill 后不允许员工继续下载，但历史下载记录保留

## 9. 测试策略

### 9.1 后端测试

至少覆盖以下场景：

- 提交 Skill 并上传 Zip 成功

- 下载最新已发布版本成功
- 下载指定历史版本成功

- 下载未发布版本失败
- 下载下架 Skill 失败
- 下载文件缺失时失败
- 下载成功后自动生成下载记录

### 9.2 前端测试

至少覆盖以下场景：

- Skill 提交表单在未选文件时不允许提交
- 新版本提交在未选文件时不允许提交

- 下载按钮在具备 `skill.download` 时可见

### 9.3 验收标准

本设计落地后，应满足：

- 员工能上传真实 Zip 提交新 Skill
- 原提交方或管理员能上传真实 Zip 提交新版本
- 员工能下载最新已发布版本

## 11. 风险与控制

### 11.1 本地磁盘占用增长

风险：

- 随版本增长，Zip 文件逐渐增多

控制：

- 本期先接受本地存储模式
- 文件元数据与存储服务接口预留后续迁移对象存储能力

### 11.2 文件缺失导致下载失败

风险：

- 运维误删文件或目录损坏

控制：

- 下载前必须检查文件存在
- 错误提示清晰暴露为“文件不存在”

### 11.3 前端低权限账号初始化报错

风险：

- 下载用户或检索用户不具备后台分类或提交权限

控制：

- Skill 页面候选接口统一走 Skill 模块受控接口
- 不直接依赖后台分类管理权限接口
