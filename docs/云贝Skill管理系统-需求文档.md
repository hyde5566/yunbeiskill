## 1. 需求概述

建立云贝Skill管理系统，集中管理员工使用的AI skill、插件、提示词等资源，解决版本混乱、来源分散、安全风险和项目追踪等问题。

系统支持skill的提交、审核、入库、发布全流程管理，提供统一的skill检索和下载能力，支持员工对skill进行评分和反馈，记录skill与项目的关联情况，确保公司内部skill使用规范化、可追溯。

### 1.1 需求背景

当前公司在AI辅助工作中面临以下问题：

1. **版本不统一**：同一skill不同员工使用版本不同，更新通知不及时，导致协作效率下降
2. **命名混淆**：同名skill众多，分享时容易混淆，沟通成本高
3. **安全风险**：部分skill存在安全隐患，缺乏统一审查机制，无法批量放心使用
4. **来源分散**：Claude Code、飞书、其他AI平台skill分散，员工查找困难
5. **缺乏追踪**：各项目使用的skill无法有效记录和跟踪，复盘分析困难

### 1.2 需求目标

上线后预期达成：

1. skill版本统一管理，员工可及时获取更新通知（站内消息）
2. skill唯一标识明确，分享指向准确无歧义
3. 审核流程落地，入库skill经人工审核确认
4. 统一检索入口，员工可快速查找需要的skill
5. 项目-skill关联记录完整，支持使用分析和追溯
6. skill评分与反馈机制完善，帮助员工判断skill质量

## 2. 角色说明

### 2.1 角色说明

系统支持角色权限自由分配，管理员可为账号配置以下权限组合：

| 权限类型 | 说明 | 包含能力 |
| --- | --- | --- |
| 基础权限 | 员工基础操作权限 | 搜索skill、下载Zip包、提交新skill、评分反馈、查看下载历史 |
| 审核权限 | skill审核操作权限 | 执行人工审核、批准/驳回入库、填写审核意见、查看待审核任务 |
| 管理权限 | 系统管理权限 | 管理skill生命周期、管理组织部门、管理项目列表、管理角色权限、查看全局统计、导出报告 |

**常见角色配置示例：**

| 角色 | 权限配置 | 说明 |
| --- | --- | --- |
| 普通员工 | 基础权限 | 可搜索、下载、提交、评分反馈 |
| 审核员 | 基础权限 + 审核权限 | 拥有员工全部权限，增加审核能力 |
| 管理员 | 基础权限 + 审核权限 + 管理权限 | 拥有全部权限 |

> 说明：角色权限可自由组合，管理员可根据实际需要为账号分配任意权限组合。

### 2.2 Skill可见范围设置

skill创建或编辑时可设置可见范围，支持三种模式：

| 可见范围 | 说明 | 适用场景 |
| --- | --- | --- |
| 全部可见 | 所有登录用户均可查看和下载 | 通用skill、公司推荐skill |
| 按项目成员可见 | 仅关联项目的成员账号可见 | 项目专属skill |
| 指定账号可见 | 管理员指定特定账号可见 | 特定人员专属skill |

> 说明：skill可见范围在创建或编辑时设置，为审核内容之一；员工只能查看和下载其可见范围内的skill。

### 2.3 用户故事

**员工视角**

- 作为员工，我希望快速找到需要的skill，避免在多个平台浪费时间搜索
- 作为员工，我希望按分类筛选skill，快速定位我需要的类型
- 作为员工，我希望下载公司已审核的skill Zip包，手动安装使用
- 作为员工，我希望skill有版本更新时能收到站内通知，及时下载新版本
- 作为员工，我希望分享skill时能准确指向，同事不会搞错
- 作为员工，我希望在使用skill后能评分和反馈，帮助其他同事判断质量
- 作为员工，我希望在必要时能下载历史版本，不强制最新版

**审核员视角**

- 作为审核员，我希望线下完成安全检查后，在线执行入库审核流程
- 作为审核员，我希望审核过程有标准检查项，避免遗漏审核维度
- 作为审核员，我本质上也是员工，拥有员工全部权限，可正常下载和评价skill

**管理员视角**

- 作为管理员，我希望统一管理所有skill的版本和状态
- 作为管理员，我希望管理组织部门架构，员工账号归属部门
- 作为管理员，我希望管理项目列表，员工关联skill时只能选择已有项目
- 作为管理员，我希望查看各项目skill下载使用情况，支持复盘分析
- 作为管理员，我希望查看skill评分统计，识别优质和问题skill

## 3. 范围说明

### 3.1 本期范围

- Skill入库管理：提交、人工审核、入库、发布全流程
- Skill版本管理：版本记录、更新提交、站内通知、历史版本查看、员工切换下载历史版本
- Skill审核管理：线下安全检查、在线审核流程、审核意见记录
- Skill检索中心：skill搜索、分类筛选、详情查看、评分展示、Zip包下载
- Skill分类管理：预设分类（AI智能、开发工具、效率提升、数据分析、内容创作、安全合规、通讯协作）、分类筛选、分类浏览
- Skill评分反馈：员工评分、使用反馈提交
- Skill下载记录管理：历史下载skill列表、当前最新版本提示、每次下载记录详情查看
- 项目管理：项目列表维护（管理员）、项目成员管理、skill可选关联项目
- 统计管理：全局统计、分类统计、评分统计、下载统计、项目维度统计、用户维度统计、数据导出
- 多来源整合：内部自研skill录入、外部平台skill导入（手动导入，来源网址标识）
- 组织部门管理：部门层级管理、员工账号归属部门、部门成员查看

### 3.2 非本期范围

- Skill在线编辑开发功能
- Skill自动采集外部平台更新
- Skill使用计费或配额管理
- 自动化安全检测工具集成
- 外部平台API深度对接
- Skill收藏功能

### 3.3 后续规划

- Skill自动版本检测与同步更新
- 线上自动化安全检测集成
- 与更多AI平台深度对接
- Skill贡献激励机制

## 4. 业务流程

### 4.1 Skill入库流程

```
1. 员工/管理员提交skill（填写来源、可选关联已有项目、上传Zip包等）
   ↓
2. 审核员线下执行安全检查（线下流程）
   ↓
3. 审核员在线执行审核，填写审核意见
   ↓
4. 审核通过 → skill入库，生成唯一标识
   审核驳回 → 返回提交方修改或终止
   ↓
5. 管理员发布skill至可用库
   ↓
6. 员工可检索、下载Zip包、评分反馈
```

### 4.2 Skill版本更新流程

```
1. skill作者/管理员提交新版本（上传新Zip包）
   ↓
2. 系统检测版本差异，标记更新内容
   ↓
3. 审核员线下检查+线上审核新版本
   ↓
4. 审核通过 → 更新入库，版本号递增
   ↓
5. 系统发送站内通知给已下载该skill的员工
   ↓
6. 历史版本Zip包保留，员工可主动下载历史版本
```

### 4.3 Skill下载与评分反馈流程

```
1. 员工搜索或浏览skill库
   ↓
2. 选择skill，查看详情、评分统计、反馈记录
   ↓
3. 选择版本，下载Zip包
   ↓
4. 员工手动安装skill到本地环境
   ↓
5. 系统记录下载时间、员工、部门、skill版本
   ↓
6. 员工使用后可提交评分和反馈
```

### 4.4 组织部门管理流程

```
1. 管理员创建部门层级结构
   ↓
2. 管理员创建/导入员工账号
   ↓
3. 将员工账号归属到对应部门
   ↓
4. 员工登录后自动关联所属部门
   ↓
5. 部门为账号的组织关系属性，不直接关联skill数据权限
```

### 4.5 项目管理流程

```
1. 管理员创建项目
   ↓
2. 管理员填写项目名称、描述等信息
   ↓
3. 项目生效，可供skill关联选择
   ↓
4. 管理员可修改或删除项目
   ↓
5. skill提交/编辑时，从已有项目列表中选择关联（可选）
```

## 6. 关键规则补充

### 6.1 状态规则

Skill生命周期状态：

| 状态 | 说明 | 可见范围 |
| --- | --- | --- |
| 待审核 | 已提交，等待审核员审查 | 审核员、管理员、提交方 |
| 审核中 | 审核员正在审查 | 审核员、管理员、提交方 |
| 已入库 | 审核通过，尚未发布 | 审核员、管理员 |
| 已发布 | 已发布至可用库，员工可下载 | 全员 |
| 已下架 | 管理员主动下架，暂停下载；历史数据保留，员工不可查看操作 | 仅管理员可见 |
| 已驳回 | 审核未通过 | 提交方、管理员 |

### 6.2 Skill基本信息规则

| 字段 | 说明 | 必填 | 适用场景 |
| --- | --- | --- | --- |
| 名称 | skill名称 | 必填 | 所有skill |
| 简介 | 简短描述，用于列表展示，建议不超过100字 | 必填 | 所有skill |
| 详细说明 | 完整说明，用于详情页展示，可包含使用方法、注意事项等 | 必填 | 所有skill |
| 作者 | skill作者名称（文本输入，非账号关联） | 必填 | 所有skill |
| 分类 | 从预设7个分类中选择一个 | 必填 | 所有skill |
| 来源类型 | 内部自研或外部平台 | 必填 | 所有skill |
| 来源网址 | 外部平台skill的来源网址链接 | 外部平台时必填 | 外部平台skill |
| 来源网址名称 | 外部平台skill的来源平台名称（如clawhub.ai） | 外部平台时必填 | 外部平台skill |
| 关联项目 | 从管理员维护的项目列表中选择 | 可选 | 所有skill |
| 可见范围 | 全部可见/按项目成员可见/指定账号可见 | 必填（创建/编辑时设置） | 所有skill |
| 可见账号列表 | 指定账号可见时选择的具体账号列表 | 指定账号可见时必填 | 指定账号可见的skill |
| Zip包 | skill文件包，大小限制50MB | 必填 | 所有skill |

### 6.3 版本规则

- 每个skill必须有唯一标识，格式建议：`{来源前缀}-{skill名称}-{版本号}`
- 版本号采用语义化版本：主版本.次版本.修订号（如 1.0.0）
- 新版本入库时，上一版本Zip包保留为历史版本，可追溯
- 员工默认下载最新已发布版本Zip包，可选择下载历史版本
- 版本更新后，系统发送站内通知提醒已下载该skill的员工

### 6.4 审核规则

- 所有skill入库前需经审核员人工审核
- 审核员线下执行安全检查（敏感信息检查、API合规性、数据外泄风险、恶意代码检测等）
- 审核员在线审核时需检查以下内容：
  - skill基本信息是否完整准确
  - 可见范围设置是否合理（全部可见/按项目成员可见/指定账号可见）
  - 关联项目是否正确
  - 内容合规性检查
- 审核员在线填写审核意见，批准或驳回入库申请
- 驳回需注明驳回原因，提交方可修改后重新提交
- 审核员同时具备基础权限时，可正常使用和评价skill

### 6.5 项目关联规则

- 项目列表由管理员统一维护（创建、修改、删除），员工不可随意填写
- skill提交或编辑时，提交方可从已有项目列表中选择关联项目（可选，非必填）
- 一个skill可关联多个项目，也可不关联任何项目
- 项目关联在入库阶段确定，不在下载阶段
- 员工下载skill时，系统自动记录下载时间、员工、所属部门、skill版本
- 管理员可按项目维度导出skill下载统计报告

### 6.6 评分反馈规则

- 员工下载使用skill后可提交评分（1-5分）和使用反馈
- 每个skill展示平均评分和评分人数统计
- 反馈内容对所有员工可见，帮助判断skill质量
- 管理员可查看评分统计，识别优质skill和问题skill

### 6.7 Skill分类规则

- 系统预设7个skill分类：AI智能、开发工具、效率提升、数据分析、内容创作、安全合规、通讯协作
- 每个skill提交时必须选择一个分类（必填）
- 分类作为Skill检索中心的重要筛选项，员工可按分类快速筛选
- 一个skill只能归属一个分类，不支持多分类
- 管理员可查看各分类下的skill数量统计

### 6.8 来源分类规则

- skill来源分为两类：内部自研、外部平台
- 外部平台skill需填写来源网址（如 https://clawhub.ai/skills?sort=downloads）和来源网址名称（如 clawhub.ai）
- 员工可按来源类型筛选skill
- skill详情页：内部自研skill显示作者信息，外部平台skill显示来源网址名称和来源网址（可点击跳转）

### 6.9 Skill可见范围规则

- skill创建或编辑时必须设置可见范围，支持三种模式：
  - **全部可见**：所有登录用户均可查看和下载
  - **按项目成员可见**：仅关联项目的成员账号可见（项目成员由管理员在项目管理中配置）
  - **指定账号可见**：提交方选择特定账号，仅这些账号可见
- 可见范围是审核内容之一，审核员需检查设置是否合理
- 用户只能查看和下载其可见范围内的skill
- 管理权限可查看全部skill（不受可见范围限制）
- skill详情页展示可见范围说明（如"全部可见"或"仅项目成员可见"）
- 编辑已发布的skill修改可见范围时，需重新审核

### 6.10 组织部门规则

- 系统支持多层级部门结构管理
- 每个员工账号必须归属一个部门
- 员工登录后自动关联所属部门
- 部门为账号的组织关系属性，不直接关联skill数据权限
- 管理员可跨部门查看和管理全量数据

### 6.11 Zip包下载规则

- skill以Zip包形式提供下载
- 员工下载Zip包后需手动安装到本地环境
- 系统不提供在线安装或自动部署功能
- 每次下载记录员工、时间、部门、skill版本信息

### 6.12 Zip包上传规则

- Zip包大小上限为50MB，超过限制时提示用户并拒绝上传
- 上传时需填写版本更新说明（提交方人工填写）
- 系统不自动检测版本差异，更新说明由提交方负责准确填写

### 6.13 审核员分配规则

- skill提交后，由管理员指定审核员进行审核
- 管理员可在审核任务列表中选择并分配审核员
- 审核员收到分配通知后执行审核任务

### 6.14 skill下架后数据处理规则

- skill下架后，历史数据（下载记录、评分记录、审核记录）保留
- 员工不可查看、下载、评分已下架skill
- 管理员可查看已下架skill的历史数据

### 6.15 操作日志与登录日志规则

- 操作日志记录用户的关键操作：skill提交、审核、发布、下载、评分、反馈等
- 操作日志字段：操作人、操作时间、操作类型、操作对象、操作详情
- 登录日志记录用户登录行为：登录账号、登录时间、登录IP、登录状态（成功/失败）
- 日志保留期限：建议保留至少180天，具体以公司合规要求为准
- 管理员可查看和导出操作日志与登录日志

### 6.16 Skill下载记录规则

- 每次下载skill时系统自动记录下载信息：
  - 下载人（账号）
  - 下载时间
  - 下载skill名称
  - 下载版本号
  - 下载人所属部门
- 历史下载skill列表展示用户已下载的所有skill：
  - 显示skill名称、作者、分类
  - 显示本人已下载的版本号
  - 显示当前最新版本号
  - 若有新版本则显示"有新版本"提示
- 下载记录详情展示每次下载的完整信息：
  - skill名称、版本号、下载时间、下载部门
- 管理员可查看全局下载统计：
  - 各skill下载总量
  - 各版本下载量分布
  - 下载排行榜
  - 各分类下载统计
- 管理员可查看指定用户或指定skill的下载记录
- 管理员可导出下载记录数据（支持按skill维度、用户维度、时间维度导出）

### 7.2 风险点

| 编号 | 风险描述 | 影响程度 | 建议应对措施 |
| --- | --- | --- | --- |
| R1 | 外部平台skill格式差异大，导入适配成本高 | 中 | 先支持主流格式，后续逐步扩展 |
| R2 | 线下安全检查可能存在漏检风险 | 中 | 建立审核规范和检查清单，定期复盘漏检案例 |
| R3 | skill更新频繁，站内通知可能打扰员工 | 低 | 提供通知频率配置，支持批量通知汇总 |
| R4 | Zip包下载后员工可能忘记安装或安装失败 | 低 | 提供安装指引文档，评分反馈中可报告安装问题 |
| R5 | 评分反馈可能存在恶意刷分或无效反馈 | 低 | 限制评分频率，管理员可标记无效反馈 |
| R6 | 部门数据权限配置复杂，可能引发权限争议 | 中 | 明确权限规则，提供权限说明文档 |
